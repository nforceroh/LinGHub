Problem. _reconnect catches MouseAbsent and MouseMisconfigured, but _connect awaits mouse.report_rates(), which the Mouse protocol documents as raising MouseLost. A mouse that vanishes between connect() and report_rates() — a KVM flick, a flat battery — escapes _reconnect, is caught by tick's blanket handler, and is logged as tick failed with a traceback. The absence never starts, so the user gets no warning and no "back after" line; they get a stack trace instead. The mouse is dropped correctly, so the next tick retries — the damage is the diagnosis, not the recovery.

Solution. _connect is the step that establishes a connection, so it should leave with a connection or with a connection failure. Translate MouseLost from report_rates into MouseAbsent there: at connect time, a mouse that vanished is a mouse that isn't there. The existing except MouseAbsent in _reconnect then starts the absence and logs it once. This restores the invariant connect() already documents — "and nothing else on purpose".

  • locality: the connect step owns what "connected" means
  • the documented invariant becomes true again
  • a KVM flick during connect reads as an absence, not a bug
  • one test pins it: report_rates raises, tick logs no bug
Deeper option: make connecting atomic — the connector returns the mouse with its capabilities, so there is no second await that can fail. That changes the MouseConnector protocol and every fake; worth it only if the capability read grows.

2. The slot reading's reason is a string protocol with a silent fallback

Strong confirmed defect
  • src/linghub/hardware/active_slot.py — SlotReadings · ActiveSlotReader.read
  • src/linghub/cli.py — format_mouse

Before — three fields, four magic strings, two fallbacks

@dataclass(frozen=True)
class SlotReadings:
    mouse: int | None
    believed: int | None
    reason: str | None = None   # "no answer" | ...
    detail: str = ""

# read(): anything unrecognised falls through
if reason == "no answer": ...
if reason == "host mode": ...
if reason == "no permission": ...
return readings.mouse          # None — "no slot active"

After — the answer is a slot or a reason

class Reason(enum.Enum):
    UNCONFIRMED_NODE = "unconfirmed node"
    NO_PERMISSION = "no permission"
    HOST_MODE = "host mode"
    NO_ANSWER = "no answer"

@dataclass(frozen=True)
class NoReading:
    reason: Reason
    detail: str = ""

@dataclass(frozen=True)
class SlotReadings:
    answer: int | NoReading
    believed: int | None

Problem. reason is a str | None carrying four magic strings, matched in two modules. Both matches end in an else that assumes the worst case: read() falls through to the success path and returns readings.mouse, which is None, so the daemon silently concludes no slot is active; format_mouse reports "the device node could not be confirmed", which is false. A typo, or a new reason added in one place only, produces a wrong answer rather than an error. The three fields also allow states that cannot happen: a reason with a mouse, or no mouse with no reason.

Solution. Make the reason a closed value and fold it into the answer. answer: int | NoReading, where NoReading holds a Reason enum and its detail. Then "the mouse said a slot" and "the mouse couldn't say, and here's why" are different types: the reason is None check disappears, both else fallbacks disappear because the enum is exhaustive, and an unknown reason becomes unrepresentable. read() and format_mouse each match once.

  • invalid states become unrepresentable
  • two silent fallbacks deleted, not centralised
  • the vocabulary lives in one module, as a type
  • tests assert the enum, not a string

3. Dead code the three PRs left behind

Worth doing deletion
  • src/linghub/hardware/mouse.py:90 — WriteResult.skipped
  • src/linghub/daemon/service.py:112 — Daemon._clock
  • src/linghub/ui/window.py:522 — MainWindow._apply_bindings
  • src/linghub/ui/panel_rules.py:113 — any_default

Problem. Four members nothing reads. WriteResult.skipped is never set true. Daemon._clock is stored and never read — the clock is already passed to Absence, so the field is a second copy of a value the class does not use. MainWindow._apply_bindings has no caller. panel_rules.any_default has no caller. Each is a small lie about the interface: a field that suggests a skip path, a field that suggests the daemon reads time, two methods that suggest a caller exists.

Solution. Delete them. If skipped is meant to come back, it comes back with the code that sets it. The clock parameter stays — Absence needs it — only the field goes.

  • four fewer things a reader has to rule out
  • no behaviour change; the tests already pass without them

4. Two write helpers that differ only in where the failure goes

Worth exploring duplication
  • src/linghub/ui/window.py:440 — _daemon_write (6 call sites)
  • src/linghub/ui/window.py:458 — _dialog_write (3 call sites)

Before — the same eight lines twice

try:
    ok = await change()
except (RuntimeError, OSError) as exc:
    REPORT(str(exc)); return False
if not ok:
    return False            # status: change said why
    # dialog: REPORT(rejected)
CLOSE()

After — one skeleton, two reporters

async def _write(self, change, report, *,
                 rejected=None, close=None) -> bool:
    ...

_daemon_write = _write(change,
    report=self._status.set_text)
_dialog_write = _write(change,
    report=dialog.show_error,
    rejected=..., close=dialog.close)

Problem. The two helpers are the same eight lines: run the change, turn a transport error into text, treat a False return as failure, refresh on success. They differ in where the text goes and whether a dialog closes. Nine call sites now depend on the duplication staying in sync.

Solution. One _write(change, report, *, rejected=None, close=None). _daemon_write passes self._status.set_text; _dialog_write passes dialog.show_error and close=dialog.close. rejected stays optional because only the dialog path has one — the status path lets the change report its own reason.

Caveat: if the merge needs a fifth parameter, stop. Two honest helpers beat one clever one.

5. The Mouse protocol is the one contract with no conformance test

Worth doing type boundary
  • tests/test_collaborators.py — PAIRS
  • src/linghub/daemon/service.py — Mouse · MouseConnector
  • src/linghub/hardware/mouse.py — RatbagMouse · RatbagConnector

Problem. test_collaborators.py ties the three D-Bus collaborators to their Protocols by signature, because a rename on one side used to fail only at runtime. The Mouse protocol — the seam the whole daemon is written against — has no such test. RatbagMouse could drift from it and the first failure would be on a user's machine.

Solution. Add a second list, SATISFIES, checked for presence and signatures but not exhaustiveness. RatbagMouse is deliberately wider than Mouse — the CLI uses slot_readings and device — so the "adds nothing" rule that fits the collaborators does not fit here. Same for RatbagConnector against MouseConnector.

  • the seam the daemon is written against becomes checked
  • the wider adapter stays wider, on purpose and on record

Small, no candidate needed

  • tests/test_writer.py and its WriterTests class still name the deleted ProfileWriter. Rename to test_mouse.py / MouseTests.
  • Absence._connected_before is a one-way latch meaning "ever connected". The name reads as "connected before this absence". Rename to _ever_connected.
  • mouse.py imports Variant locally in three methods while DBusError is module-level. Hoist it.
  • WriteResult.changed is built by four appends and read once, as len(...). Either log the names or make it a count.
  • Report() with no message is a sentinel for "nothing to say"; None would say it directly.
